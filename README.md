# ローカルLLMを活用した社内文書RAGシステム

社内文書を想定したテキストデータを対象に、ローカルLLMである Qwen3-4B を使用したRAG（Retrieval-Augmented Generation）を構築しました。

文書本文だけでなく、ファイル名・保存場所をメタデータとして保持し、回答とあわせて参照元を確認できる構成にしています。

また、参照文書に回答の根拠が存在しない場合には、LLM自身の知識や推測で補完せず、回答を拒否するようにプロンプトを調整しています。

## 主な特徴

- Qwen3-4Bをローカル環境で回答生成モデルとして使用
- 社内文書を想定した階層構造を持つテストデータを使用
- ファイル名・保存場所をメタデータとして保持
- RecursiveCharacterTextSplitterによるチャンク分割
- multilingual-e5-baseによるEmbedding
- Chromaによるベクトル検索
- Retrieverで取得した文書をContextとしてQwen3へ入力
- 回答とあわせて参照元のファイル名・保存場所を表示
- 参照文書に根拠がない質問への回答を抑制
- Qwen3-1.7BとQwen3-4Bで回答品質を比較

## 処理の流れ

```text
社内文書（テキストファイル）
        ↓
LangChain Document
        ↓
チャンク分割
        ↓
Embedding
        ↓
Chromaへ登録
        ↓
Retrieverで関連文書を検索
        ↓
Contextを作成
        ↓
Qwen3-4B
        ↓
回答 + 参照元
```

## 実行例

### 社内文書に回答が存在する質問

質問：

```text
パソコンが故障した場合はどこに問い合わせればいいですか？
```

回答：

```text
パソコンが故障した場合は、情報システム部へ速やかに報告してください。
```

回答とあわせて、Retrieverが取得した文書のファイル名と保存場所を出典候補として表示します。

### 社内文書に回答が存在しない質問

質問：

```text
日本で一番高い山は？
```

回答：

```text
データ上にない情報なのでお答えできません。
```

この場合は、無関係な検索結果を出典として表示しないようにしています。

## 検証

明確な質問だけでなく、以下のパターンでも動作を確認しました。

- 短く曖昧な質問
- 文書とは異なる表現を使った質問
- 文書に回答が存在しない質問

また、当初使用していた Qwen3-1.7B では、参照文書に明記されていない内容を推測して回答するケースがありました。

プロンプトによる制約を追加したうえで Qwen3-4B に変更したところ、今回の検証では、根拠のない質問に対して回答を拒否する動作を確認できました。

詳細な実装・検証結果はNotebookに記載しています。

## 今後の改善点

現在はRetrieverが取得した上位3件を出典候補として表示しているため、回答生成に直接使用していない文書が含まれる場合があります。

今後は検索スコアによる絞り込みや、回答生成で実際に使用した文書を判定する仕組みを追加し、出典表示の精度を改善する余地があります。

## 注意事項

本リポジトリで使用している社内文書は、RAGの動作確認を目的として作成したダミーデータです。

実在する企業・組織の社内文書ではありません。
